A peer-to-peer messenger on the Tor network. There is no server: every account is its
own onion service, and the onion address is the username.

## Download

| Platform | File | Notes |
|---|---|---|
| Windows x64 | `darkflow-0.1.0-windows-x64.zip` | Unzip anywhere and run `darkflow.exe`. The `tor` folder beside it is the daemon; move the whole folder, not just the executable. |
| Android (arm64) | `darkflow-0.1.0-android-arm64.apk` | Signed. arm64 devices only; there is no 32-bit or x86 build, deliberately. |

**Windows: the binaries are unsigned**, so SmartScreen will say the application is
unrecognised. That warning is indistinguishable from the one a malicious binary
produces, and there is no certificate behind this release. Check the SHA-256 below
against what you downloaded before running it.

## What is in it

- **Accounts.** Argon2id over the password, an Ed25519 identity, an X25519 exchange
  key, an optional six-digit PIN bound to the OS keystore, and an encrypted vault with
  no database engine.
- **Tor bundled and managed by the application.** Bridges for obfs4, WebTunnel,
  Snowflake, meek and conjure, with a validator that refuses a malformed bridge line
  before Tor ever sees it.
- **Messaging over Tor**: handshake with a pinned identity key, a symmetric ratchet,
  encrypted attachments sent in chunks, delivery and read receipts, replies, drafts,
  and search inside a conversation.
- **Voice messages**, recorded with a waveform and encrypted at rest.
- **Relaying between contacts** who opted in, with an outbox, backoff and a mailbox pull.
- **Diagnostics**: an in-application report with the Tor log, mesh state and an event
  log written to disk, so a failure can be described rather than guessed at.

## Fixed in this release

These are the faults behind the two reports that kept coming back: "the contact
appears only after a restart", and "messages do not arrive".

- A contact learned from an inbound handshake never received a conversation, so it
  existed in storage and appeared nowhere until a restart rebuilt the list.
- Eight methods wrote to memory before disk, leaving records visible on screen and
  absent from the vault. The order is now storage-first throughout.
- Overlapping writes to one store sink raised `StreamSink is bound to a stream` and
  lost the write. Each collection now has a write queue that `close`, `flush` and
  `compact` drain.
- Concurrent dials to one peer were started on top of each other. A real diagnostics
  report showed twenty-four simultaneous SOCKS dials to one address; they now share a
  single attempt.
- A failed inbound handshake was caught and dropped, making it indistinguishable from
  "nobody called". Failures are logged with a reason.
- **Voice playback** showed no progress while the audio was already audible. Four
  independent causes: the "now playing" mark was set after the file was decrypted; the
  phone layout passed it to a pushed route as a snapshot; the decrypting loop blocked
  the frame that would have redrawn the control; and a missing platform completion
  signal left the button on pause for ever.
- **The QR scanner** could show an unexplained black rectangle, because the camera
  plugin renders an empty box when it has no texture. The explanation is drawn
  underneath the preview now, so that area is never blank.

## Removed

- **Voice and video calls.** They cannot cross Tor without a custom Opus-over-TCP media
  relay, and a call button that connects sometimes is worse than none. The code was
  deleted rather than disabled, so nothing in the interface claims it exists.
- **The Android foreground service.** It kept the process alive for alerts that still
  could not be guaranteed, at the cost of a permanent notification and battery.

## Known gaps

- **No Windows installer**, and the binaries are **unsigned**.
- **iOS is not built**: the App Store forbids shipping an executable Tor.
- **Android is arm64-v8a only.**
- **No group chats, no multi-device sync.**
- **No forward secrecy** against someone who steals a long-term key *and* a relay's
  stored envelope.
- **Not independently audited.**
- **Delivery has not been observed between two real devices over Tor.** It is covered
  by tests (the storage ordering, the conversation creation, the shared dial, the
  inbound handshake, and the voice playback chain), and each fix is checked by
  deliberately breaking it and confirming a test fails. That is not the same as a field
  test, and this note will not pretend otherwise.

The full list, with reasons, is in `docs/RELEASE.md` section 5.
